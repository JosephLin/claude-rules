# 2026-09: orchestrating agent sessions hands-off, safely

The baseline for the monthly reviews. It was written in a main session on
2026-09-24 and is what the Working style section in `CLAUDE.md` is based
on.

## Findings

- **Harness rules go stale as models improve.** "Every component in a harness
  encodes an assumption about what the model can't do." With Opus 4.6, Anthropic
  removed sprint decomposition one piece at a time. [Anthropic, harness design
  (2026-03)](https://www.anthropic.com/engineering/harness-design-long-running-apps)
- **Keep writes single-threaded.** Extra agents should add review and planning,
  not edits. A reviewer with fresh context finds about 2 bugs per PR, 58% of them
  severe. [Cognition, "Multi-Agents: What's Actually
  Working" (2026-04)](https://cognition.com/blog/multi-agents-working)
- **Self-evaluation fails; a separate evaluator works.** The evaluator exercises
  the running app against success criteria agreed before building. A full harness
  cost $200 against $9 solo, worth it only beyond what one agent does reliably.
  (Same Anthropic post.)
- **Tests are both the oracle and the weak point.** 16 parallel agents built a C
  compiler over about 2,000 sessions for $20k, and overwrote each other when they
  all hit the same bug. [Anthropic, C compiler
  (2026-02)](https://www.anthropic.com/engineering/building-c-compiler) Models edit
  tests to pass. [METR (2025-06)](https://metr.org/blog/2025-06-05-recent-reward-hacking/)
  The gap between visible and held-back tests grows with task size.
  [SpecBench (2026)](https://arxiv.org/html/2605.21384v1)
- **Coordinate through files and git, not chat.** Examples: progress files, lock
  files in git, a shared task list.
- **The open problems are communication problems**: when to escalate, and what to
  ask. Claude Code Projects recommends one pilot thread before a batch.
  [Projects docs](https://code.claude.com/docs/en/claude-projects)
- **Safety comes from structure.** The "lethal trifecta" is private data plus
  untrusted input plus network access; the answer is a sandbox.
  [Willison](https://simonwillison.net/tags/lethal-trifecta/) Auto mode's
  classifier has 0.4% false positives but misses 17% of real overeager actions,
  and isn't a replacement for review on high-stakes infrastructure.
  [Anthropic, auto mode](https://anthropic.com/engineering/claude-code-auto-mode)
- **Context files:** on average they didn't raise task success but raised cost by
  over 20%. Minimal, human-written ones are best.
  [Gloaguen et al. 2026](https://arxiv.org/abs/2602.11988)
- **Capability trend:** METR time horizons double roughly every 3–4 months.
  [METR TH 1.1](https://metr.org/blog/2026-1-29-time-horizon-1-1/)

## Tooling as of this month

- Claude Code **Projects** (public beta, Pro/Max): a coordinator conversation
  plus threads that report back, an Overview pane with *Waiting on you*, shared
  instructions and memory, and threads on your Mac through Remote Control. Public
  beta, rolling out gradually.
- **Cross-session messaging:** local sessions message each other both ways. A
  cloud session can receive but can't reply. A message never grants
  permission. [Docs](https://code.claude.com/docs/en/cross-session-messaging)
- **Agent teams** (experimental): a lead, teammates, a task list with file locks,
  and hooks for quality gates. They can't be resumed, and there's one team per
  session. [Docs](https://code.claude.com/docs/en/agent-teams)

## What changed in the rules

`CLAUDE.md` Working style: main defines tasks; `TASKS.md` is the queue;
one writer per area; fresh-context review; structural safety; milestone branch;
the process is provisional. All CLAUDE.md files were trimmed to short, high-level
defaults.
