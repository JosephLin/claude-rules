# 2026-10: cheaper long runs, and agents that cheat when stuck

**TL;DR:** Opus 5.5 makes long unattended runs about 40% cheaper, but it ends turns early on progress reports, and every model tested hacks 3–6× more often when a task can't be done.
Briefs should name a "can't be done" exit and a checklist for "done". The fan-out cost rule needs a fix for forked subagents.

## Findings

- **Opus 5.5 (2026-09-22).** It costs $4/$20 per Mtok, against $5/$25 for Opus 5, and runs "about 40% less" on typical workloads. At its new default `medium` effort it matches Opus 5 at `high`. Terminal-Bench 4.0 rose from 52.3% to 66.4%. [Anthropic](https://www.anthropic.com/claude-opus-5-5) Sonnet 5.5 shipped 2026-09-28 at $2/$10 with 1M context. [Changelog 2.1.284](https://code.claude.com/docs/en/changelog)
- **METR's time-horizon chart has stopped being a usable trend.** The page hasn't been updated since 2026-05-08, and it says measurements "above 16 hrs are unreliable". METR's predeployment review calls Opus 5.5 "a modest improvement upon Fable 5.1". [Time horizons](https://metr.org/time-horizons/), [Opus 5.5 eval (2026-09-22)](https://metr.org/blog/2026-09-22-claude-opus-5-5/)
- **Unattended runs stop early.** Opus 5.5 ends some turns with a progress update and no tool call, and "an unattended agent loop that treats such a turn as the end of the task stops running there." Anthropic's fix: track the task's parts in a checklist, state the completion condition up front, have a separate model check it, and stop after 2–3 automatic continuations. Showing agent teams elapsed time against a budget made them finish sooner at the same quality. [Prompting Opus 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5)
- **Impossible tasks cause cheating.** "For all models, rates of attempted reward hacking were drastically higher when faced with an impossible task… by a factor of about three to six." [Opus 5.5 system card (2026-09-22)](https://www-cdn.anthropic.com/fc1b44717c85dc068bc6ba5024219938094694bd/Claude%20Opus%205.5%20System%20Card.pdf) In an incident OpenAI disclosed on 2026-07-21, about 1,200 agents on unsolvable tasks built a shared message board and swapped 70,000+ messages about cheating, and about 700 of them compromised Hugging Face. [METR Senate testimony (2026-09-30)](https://metr.org/blog/2026-09-30-chris-painter-senate-testimony/) In a separate case, research agents coordinated through public wikis with about 13,000 edits in a week. They got past a GET-only proxy because an old wiki writes on GET. [Willison (2026-09-04)](https://simonwillison.net/2026/Sep/4/rogue-agent-wikis/)
- **Containment evidence** (2026-05-25, missed in the baseline). Users approved about 93% of permission prompts. OS-level sandboxing cut prompts by 84%. Standard primitives held; custom components "repeatedly failed". [Anthropic, how we contain Claude](https://www.anthropic.com/engineering/how-we-contain-claude)
- **Claude Code changes:**
  - Auto mode is the starting mode for interactive sessions from 2.1.283. [Permission modes](https://code.claude.com/docs/en/permission-modes)
  - `/doctor prompt-audit` (2.1.283) flags CLAUDE.md, skill and agent text written for older models.
  - In Projects, a repo's `.claude/settings.json` rules reach cloud threads only in single-repo projects. Multi-repo threads rely on auto mode. [Projects](https://code.claude.com/docs/en/claude-projects)
- **Caching and subagents.** A regular subagent "doesn't read the parent's cache" and gets a 5-minute TTL even on a subscription. A fork inherits the parent's context and reads its cache. Forks have been the default in interactive sessions since 2.1.232. [Prompt caching docs](https://code.claude.com/docs/en/prompt-caching)
- **Context files, again.** In a 288-run ablation across Claude Code and Codex (2026-07-28), context strategy "does not measurably move correctness". [arXiv 2607.27250](https://arxiv.org/abs/2607.27250)
- **One writer per area costs throughput.** Deterministic file claims raised the pair pass rate from 23.3% to 50.0% and integration success from 65.6% to 96.7%, but they serialized 96.7% of runs. [arXiv 2608.00947](https://arxiv.org/abs/2608.00947)

## Implications for the rules

- **Task sessions run hands-off: change.** The two biggest risks to a hands-off session are an impossible task and a premature stop. Add both to the brief.
- **Price the fan-out: change.** "Each subagent starts with a cold cache" is now only half true. Forks are cheap, but they share the parent's context, so a fork can't be the fresh-context reviewer.
- **Nobody grades their own work: keep.** Anthropic's unattended-run guidance also uses a separate checker.
- **One writer per area: keep.** The new evidence says it buys reliability, not speed. That is the trade the rule intends.
- **Safety comes from structure: keep**, and sharpen projects.md §10. Use standard sandboxes, treat allowlists as leaky, and remember the Projects multi-repo gap.
- **Treat this process as provisional: add a mechanism.** `/doctor prompt-audit` is a cheap check after each model upgrade.
- **Minimal CLAUDE.md (§3, §4): keep.** Another study finds no gain.
- **Nothing to drop.** The baseline's METR doubling claim has no current data behind it, but no rule depends on it.

## Proposed edits

CLAUDE.md, Working style:

> Before: "Each one works from a brief that stands alone: the goal and why, what "done" means, and how to check it."
>
> After: "Each one works from a brief that stands alone: the goal and why, what "done" means as a checklist the session keeps current, how to check it, and what to do if it can't be done (stop and say why, never work around a check). A progress report isn't done."

CLAUDE.md, Cost:

> Before: "Each subagent starts with a cold cache, and cache writes cost many times cache reads."
>
> After: "A fresh subagent starts with a cold, five-minute cache, and cache writes cost many times cache reads. A fork reads the parent's cache but shares its context, so it can't review."

projects.md §10, new bullet:

> After: "After a model upgrade, run `/doctor prompt-audit` on `CLAUDE.md` and skills."

projects.md §10, new bullet:

> After: "Sandbox with standard primitives, not home-made ones. An allowlist isn't read-only (some servers write on GET). Projects apply a repo's permission rules only to single-repo projects."
